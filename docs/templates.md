# テンプレート生成

シチュエーション・キャラクター・絵柄の 3 つを保存しておき、組み合わせてプロンプトを
組み立てるしくみ。単一ユーザー向けなので、共有や権限まわりの概念は持たない。

保存先はローカル API のコレクション（`<configDir>/collections/*.json`）。
画像はアセット（`<configDir>/assets/`）。仕様は [api.md](api.md) を参照。

## 生成モード

パネル最上部でモードを切り替える。選んだモードは localStorage に残る。

| モード | 中身 |
| --- | --- |
| 通常 | プロンプトを直接書いて生成する。プロンプト欄とキャラクター欄が出る |
| バッチ | シチュエーション・キャラクター・絵柄を選んで生成する。プロンプト欄は出ない |

**バッチはプロンプト欄に書き込まない。** 押した瞬間にシーンごとのプロンプトを
組み立てて、そのまま生成する。1 回の生成が複数のシチュエーションにまたがるので、
プロンプト欄 1 つには収まらない——書き込む設計にすると 1 シチュエーションで打ち止めになる。

### 選ぶのは 3 つ、それぞれポップアップで完結させる

| 欄 | ポップアップ | 選び方 |
| --- | --- | --- |
| シチュエーション | `situation-picker-dialog.tsx` | **複数選択。**グループ行のクリックでまとめて選ぶ |
| キャラクター | `character-picker-dialog.tsx` | 複数選択。画像を見て選び、立ち位置もここで決める |
| 絵柄 | `style-picker-dialog.tsx` | 1 つだけ。モデルと生成パラメータも絵柄が決める |

パネルに残るのは要約だけ（「5 件選択中」＋グループのチップ）。件数が増えると
パネルの幅では選べないので、選ぶ作業はポップアップの側でやる。

### 生成の単位

```
生成枚数 = シチュエーション数 × 枚数
```

並びはシーンメジャー——1 シーン分を撮り切ってから次のシーンへ進む。履歴が
1 グループにまとまり、出てくる順番が選んだ順番と一致する。

キャラクターと絵柄は全シーンで共通。バイブのエンコードは 1 回の生成につき 1 回
（シーンごとに送ると 1 回 2 Anlas かかる）。

シーンの文面もキャラクターの文面も両方空になるシチュエーションは落とす。
品質タグだけの画像に 1 枚使ってしまうため。判定は品質タグと絵柄を足す**前**に行う
（足したあとは絶対に空にならないので、判定が意味を持たない）。

## 役割分担

**文面はシチュエーションが持ち、キャラクターは値だけを持つ。**
ここが分かりにくいところなので先に書いておく。

| | 持っているもの |
| --- | --- |
| シチュエーション | 4 つのテンプレート。`{token}` を含む文面 |
| キャラクター | `{token}` に入る値（`hair_color` → `silver hair` など）＋ 主体（gender） |
| 絵柄 | 絵柄タグ・挿入位置・生成パラメータの上書き・参照画像 |

### 主体（gender）はキャラ文面の先頭に入る

`girl` / `boy` / `other` の 3 つ。テンプレートを通さず、組み立て時に
`char_caption` の**先頭**へ直接足す（本家 NovelAI と同じ）。

V4 はキャラごとの文面を別々に読む。属性だけの文面
（`ponytail, white hair, thighhighs`）には主体を表す語が無く、
モデルはそれを誰に付けるか決められない。複数人を指定しても 1 人に混ざるのは
たいていこれが原因。

テンプレートの `{token}` にしていないのは 2 つ理由がある。
先頭でなければ効きが弱いこと、そしてシチュエーション側が書き忘れても
必ず入っていてほしいこと。

**設定できる場所は 2 つ。** どちらも本家と同じく「キャラクターの上」に置く。

| モード | 場所 | 保存先 |
| --- | --- | --- |
| 通常 | キャラクターカードのプロンプト欄の上 | フォーム（その生成かぎり） |
| バッチ | キャラクターポップアップのキャスト一覧 | キャラクターのレコード |

バッチ側がレコードに書き戻すのは、選択状態を保存していないため。
生成ごとの値にすると再読み込みのたびに消える。髪色と同じくキャラクターの性質なので、
一度決めれば以後ずっと効く。

先頭へ付けるのは `buildGenerateRequest` の 1 か所だけ。組み立て側は
`gender` を entry に載せて渡すだけにして、位置を決める場所を 2 つにしない。

キャラクター自身も `positiveTemplate` を持つが、**生成では使わない**。
管理画面のプレビュー用。生成に効くのはシチュエーション側のテンプレートだけ。

同じキャラクターをどのシチュエーションにも差し込めるのは、この分け方のため。

## シチュエーションの 4 テンプレート

| フィールド | 送り先 |
| --- | --- |
| `basePrompt` | 画面全体のプロンプト（V4 の `base_caption`） |
| `baseNegative` | 画面全体のネガティブ |
| `characterPrompt` | キャラ 1 人分（V4 の `characters[].char_caption`） |
| `characterNegativePrompt` | キャラ 1 人分のネガティブ |

シーンとキャラクターは NovelAI V4 が別々に受け取るので、最後まで混ぜない。
V3 系はキャラを分けて送れないため、そのときだけ 1 本のプロンプトへ畳み込む。

`{additional}` `{additional_negative}` `{additionalcharacter}`
`{additionalcharacter_negative}` の 4 つは各フィールドの末尾に必ず入る追記枠で、
消せない。シチュエーションが想定していないものをキャラクター側から足すための穴。

トークンの一覧は文面から毎回作り直す（`syncSituationVariableKeys`）。
文面が正で、一覧は結果。手で合わせない。

### 定型トークンは入力欄に出さない

アプリが自分で入れるトークン——キャラクター定型（`{copyright_tag}` など 10 個）と
上の追記枠——は入力欄から抜いて、上のチップだけで扱う。どのシチュエーションでも
同じ中身なので、入力欄に残すとその場面のために書いた文が埋もれる。

| | チップ | 消せるか |
| --- | --- | --- |
| キャラクター定型 | 常に 10 個並ぶ。入っていないものは打ち消し線 | ✕ で外す・＋ で戻す |
| 追記枠 | ＊ 付き | 消せない |
| 自分で足したトークン | 入っているものだけ | ✕ で外す |

入力欄が持つのは抜いたあとの文面だけなので、編集のたびに
`mergeManagedSituationTokens` が今あるトークンを後ろへ戻して全文を作り直す。
これをしないと 1 文字打っただけで定型が消える。

保存される順番は「自由文 → 定型 → 追記枠」になる。

トークンを足す口は入力欄だけ。`{key}` と書けば blur で拾われるので、
専用の追加欄を別に置くと同じことをする道が 2 つになる。

### 入力欄の補完は 2 種類

キャレットが書いている途中のものによって候補が変わる（`getCurrentBraceToken`）。

| キャレットの位置 | 候補 |
| --- | --- |
| 閉じていない `{` の中 | テンプレートトークン。`{` だけで全件出る |
| それ以外 | Danbooru タグ（他の入力欄と同じ） |

トークンの候補は 3 か所から集める。キーは両側が同じ綴りで書いて初めて意味を持つので、
片側だけを見ても足りない。

- キャラクター定型 10 個
- 他のシチュエーションが既に書いているトークン
- キャラクターが値を持っているキー（キャラクターエディターの
  「どのシチュエーションも使っていない値」を繋ぎ直す口になる）

### 入力欄の文字はそのまま持つ

`stripManagedSituationTokens` / `mergeManagedSituationTokens` は
カンマ分割して組み直さない。組み直すと打った瞬間のカンマが空要素になって消え、
2 つめのタグを書き始められない。定型トークンは**リテラル文字列**として
`{key}` を探して切る。入力欄はトークンを打つ場所でもあるので、
数キーのあいだ `{` が閉じていない状態を必ず通る——その瞬間に構文解析すると
隣の本物のトークンまで巻き込む。

## キャラクターの入力欄はシチュエーションから作る

キャラクターが持つのは値だけで、文面はシチュエーションが持つ。生成は
シチュエーションの 4 テンプレートをキャラクターの値で展開するので、
**どのシチュエーションも書いていないキーの値は、どこにも届かない。**
だからキャラクターエディターの入力欄は固定リストではなく、
シチュエーション側のトークンの和集合から作る（`collectSituationVariableKeys`）。

| 欄 | 中身 |
| --- | --- |
| 参照 | どのグループのシチュエーションから作るか。既定はすべて |
| 値入力 | 参照したシチュエーションが書いているトークン。順番は最初に出てきた順 |
| 追加スロット | `{additional*}` の 4 つ。シチュエーションに関わらず常に出す |
| どのシチュエーションも使っていない値 | キーがどこにも無いのに値がある行。畳んである |

追加スロットを和集合から外しているのは、どのシチュエーションにも必ずあって
参照を切り替えても増減しないため。`{additional}` と `{additional_negative}` は
シーン側の枠なので、先頭のキャラクターの値だけが使われる（`compose.ts`）。

「使っていない値」を隠さないのは、投射だけにするとキーが消えた瞬間に
値が編集できなくなるため。判定は参照中ではなく全シチュエーションに対して行う。

キャラクター自身の `positiveTemplate` / `negativeTemplate` / `negativePrompt` は
生成では使わない。一覧とプレビューの表示だけなので、エディターでは畳んである。

## キャラクターの選び方と立ち位置

名前だけでは誰なのか分からないので、キャラクターには画像を 1 枚持たせる
（`imagePath`。アセットとして保存し、差し替え・削除・複製で追従する）。
選択は画像のグリッドから行う。クリックで追加・解除し、モーダルは閉じない。

**立ち位置は全員分を 1 つの枠で指定する。** 決めているのは
「他の誰に対してどこか」なので、1 人ずつ別の枠を出すと肝心の並びが見えない。
枠は選んだ解像度と同じ縦横比を取り、セルにはキャラクターの画像が入る。
選択中のキャラクターがセルをクリックで入り、そのまま次のキャラクターへ進む。
自分のセルをもう一度押すと外れる（座標を送ると `use_coords` が入り、
構図が固まりやすいため「指定なし」を残しておく必要がある）。

**バッチでは、このグリッドはポップアップの中だけに置く。** パネルには
キャストの一覧（順番・立ち位置の表示・並べ替え・外す）だけを残す。

通常モードのキャラクター欄も同じグリッドを使う。あちらはポップアップが無いので
欄の中に置く。こちらは id が無いので並び順の添字で持ち、入力欄にフォーカスした
キャラクターが選択中になる。

## 組み立ての順序

```
prompt   = 品質タグ群 + 絵柄タグ + basePrompt を展開したもの
negative = ネガティブプリセット + 絵柄ネガティブ + baseNegative を展開したもの
characters[n] = characterPrompt をキャラ n の値で展開したもの
```

絵柄タグの位置は絵柄の `promptPosition` で決まる。

| 値 | 並び |
| --- | --- |
| `start` | 絵柄, 品質タグ群, 本文 |
| `after_quality`（既定） | 品質タグ群, 絵柄, 本文 |
| `end` | 品質タグ群, 本文, 絵柄 |

**`{token}` の展開は先頭のキャラクターの値で行う。** シーンは画像全体に 1 つしかないので、
並び順を変えると場面の文面も変わる。

値が無いトークンは空になり、カンマごと落ちる。半分しか埋めていないキャラクターでも
カンマが余らない。タグの重複は取り除かない（NovelAI では重ねると強調になるため）。

## 品質タグとネガティブプリセット

組み立て時にクライアント側で本文へ書き込み、リクエストは `quality: false` /
`uc_preset: "none"` で送る。サーバ側の自動付与と二重にならないようにするため。

バッチではこの切り替えを生成の瞬間にシーンごとのフォームへ入れる。詳細設定の
トグルは触らない——押すたびにパネルの表示が書き換わると、次に通常モードへ
戻ったときに勝手に変わっていることになる。

## 絵柄の上書き

`model` `steps` `scale` `cfgRescale` `varietyBoost` `sampler` `noiseSchedule` は
`null` なら「上書きしない」。値が入っているものだけがフォームへ入る。
入ったあとは普通に編集できる（絵柄の値を直接送るわけではない）。

バイブ転送と精密参照はどちらか一方しか送れない。絵柄が両方を持っている場合は、
そのときのパネルのモードに従う。
